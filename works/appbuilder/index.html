Project Overview

The Proposal

Stemming from an internal innovation project,  design and build a way for users to create web applications. Current methods of doing this are based in the organizations' desktop product. We needed to bring this functionality to the cloud suite and enhance the user experience.

Goals

We needed to design and build a way for users to create front-end web applications that uses workflows as the back end. This needs to be a feature within Designer Cloud, just like it is embedded in Designer Desktop product. The feature needs to be able to connect workflow tools to simple HTML components, like drop downs, check boxes, and tables. Users should be able to deploy this website for external users.

Challenge

Does this feature fit inside of another product? How can we enhance the user experience for this product and increase adoption?

Solution + Prototype

After ideating with UX leadership and with cross-product teams, we decided that this idea would be better as it's own cloud product because it was too robust and had opportunity to grow exponentially.

The new cloud product provided a way for users to add tools to a canvas, which followed Alteryx canvas patterns for customer familiarity and adoption. Each tool connected to a workflow tool and was customizable for the application creator. The application was deployable to external facing customers. Also, we added the ability for users to design in desktop, tablet, or mobile canvases.

Designing Process - Highlights

Identifying Personas + User Flow

It was important to identify to help conversations internally amongst the product team and leadership. We identified a new persona for Alteryx, the Consumer. This persona was identified through a simple user flow.

‍

Research + Product Knowledge

Building applications is not new to Alteryx, but it was new to our cloud suite and we needed to update our patterns. I spent a lot of time analyzing and building websites in no-code web developer products like Webflow and WordPress to learn about common patterns so users would have familiarity. I also noted pain points in these websites which I attempted to alleviate in my designs for our product.

Noteable Patterns
  • Borders to define space a component will use on the screen
  • Drag and drop icons and transitions
  • Multiple panels to organize information for configurations and styling
  • Editing a component within the canvas and not just within a panel
Pain Points
  • No visual cue for data-backed components compared to regular components
    • Example, a data-populated table vs. a heading
  • Loading states
  • Designs for mobile, table, and desktop seamlessly working together if a user edits in one format compared to another

Lessons Learned

  • Defining and growing a new product into an established suite of products
  • How to work through limitations in a growing platform
  • Working under pressure to deliver milestones to leadership and users fast

Next Steps

After I designed the backbone of the product and helped our team get Alteryx App Builder to market, I handed this project off to another designer to continue working with the team.
